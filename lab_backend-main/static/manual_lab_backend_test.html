System flow

How the lab backend works

The backend now behaves like a doctor-only orchestration layer. The UI below is arranged to follow the same order the service uses internally.

1

Authenticate doctor

Use the frontend-managed session, then exercise the backend routes directly.

2

Load patient context

Patients, diabetic data, heart data, reports, and histories are all keyed by the same patient ID.

3

Build the agent job

The lab agent validates the patient and report IDs, then prepares a ready or awaiting-trend job.

4

Ingest evidence and analyze

Trusted sources are chunked locally, Gemini is called with citation rules, and outputs are validated.

5

Run OCR and trends

OCR happens in the background and trend analysis only becomes active once the report history is sufficient.
